# 怎么维护文档

设计文档只放在仓库的 `__DOCS_DIR__/` 目录里，改完 push 到 `__BRANCH__`，网站自动更新。人和 AI 都按下面的规则写；AI 的入口规则在仓库根目录的 `AGENTS.md`，它会指向本页。

## 什么内容写在哪

<!-- 每个项目按自己的目录改这张表；AI 会照这张表决定改哪一页。 -->

| 内容 | 写在哪 |
| --- | --- |
| 首页：文档一览和阅读顺序 | `index.md` |
| 本站怎么用、怎么维护 | `guide/` |

## 写法

- 一页只讲一件事。开头第一段写结论；内容改了，结论也跟着改。
- 过时的描述直接删掉，不留“以前是……”。需要历史就看 git 记录。
- 一件事只写在一个地方，别的页面需要时链接过去，不复制。
- 用平常的话写给人看；版本、路径、数字这类给 AI 用的细节放在页面末尾。

## 加一个页面

1. 在对应目录里新建 `NN-名字.md`，第一行是 `# 标题`。侧边栏按文件名排序，用 `01-`、`02-` 前缀控制顺序。
2. 新建目录时，放一个 `index.md` 作为这一组的首页，它的标题就是侧边栏里的组名。
3. 页面之间用相对链接，例如 `[运行时](./06-runtime.md)`。

## 放图解（HTML）

1. 把 HTML 文件放到 `__DOCS_DIR__/public/embeds/名字.html`。
2. 在页面里单独写一行：`<Embed src="/embeds/名字.html" title="图解标题" />`，可以加 `height="900"` 调高度。
3. 图解保持 HTML，不要改写成文字或截图；页面旁边用几句话写清楚图里讲了什么，给不能看图的人和 AI。

## 检查与同步

- 改完运行检查：`npm --prefix __DOCS_DIR__ run check`。有 error 必须修好再提交；网站构建时也会跑这个检查，error 会让部署失败。
- 本地预览：`npm --prefix __DOCS_DIR__ run dev`，然后打开它打印的地址。
- 同步：Claude Code 每次开会话时自动取一次远端的 `__BRANCH__`。能安全快进时直接更新；本地有没推的提交、或者未提交的改动挡住了更新时，什么都不动，只提醒 AI 先处理，不会自己弄出冲突。在功能分支上只取不合并，AI 用 `git show origin/__BRANCH__:__DOCS_DIR__/页面.md` 读最新版。
- 改完由 AI 提交并 push。手动小改可以在网页上点“在 GitHub 上编辑本页”。
- 两个人同时改了同一页会出现 git 冲突，交给 AI 和你一起合并。
